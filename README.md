# RUMBAI — персональный AI-командный центр

Мобильное PWA для iPhone 16 Pro Max и любых других экранов: ассистент, задачи, заметки, база знаний, файлы, автоматизации и управление моделями ИИ. Приватность по умолчанию: данные хранятся на устройстве, облако включается только явно.

## Быстрый старт

Нужен Node.js 22.6 или новее: сервер на TypeScript запускается через `--experimental-strip-types`.

```bash
git clone https://github.com/wwgame28/Rumbai.git
cd Rumbai
npm ci
npm run build          # проверка типов и сборка в dist/
npm start              # сервер на http://localhost:8787 (dist + /api)
```

Разработка с горячей перезагрузкой, в двух терминалах:

```bash
npm run dev:server     # API на :8787
npm run dev            # Vite на :5173, /api проксируется на :8787
```

Проверки:

```bash
npm run typecheck      # TypeScript
npm run lint           # ESLint
npm test               # модульные тесты и тесты сервера (node:test)
npm run test:e2e       # Playwright: собирает проект и поднимает сервер на :4317
npm run check          # typecheck + lint + test + build
```

## Облачный ИИ (Claude), необязательно

Без ключа приложение полностью работает: задачи, заметки, файлы, локальная модель. Для облачного режима задайте переменные окружения **на сервере**:

| Переменная | Назначение |
|---|---|
| `ANTHROPIC_API_KEY` | ключ Anthropic API, обязателен для облака |
| `CLAUDE_MODEL` | по умолчанию `claude-opus-5-5` |
| `CLAUDE_EFFORT` | `low` / `medium` (по умолчанию) / `high` / `xhigh` / `max` |
| `PORT` | порт сервера, по умолчанию 8787 |
| `ALLOWED_ORIGINS` | дополнительные разрешённые Origin через запятую; свой origin разрешён всегда |

Образец лежит в `.env.example`. Ключ не должен начинаться с `VITE_`: такие переменные попадают в браузерный бандл. Ключ читается только в `server/index.ts`.

Как устроен сервер (`server/`):
- использует официальный SDK `@anthropic-ai/sdk` и стримит ответ в браузер через SSE;
- включает `fallbacks: "default"` (бета `server-side-fallback-2026-07-01`): если модель откажется отвечать, Anthropic повторит запрос на резервной модели;
- проверяет каждый запрос через zod;
- ограничивает размер тела (512 КБ), частоту запросов (30 в минуту с одного адреса) и разрешённые Origin;
- описания инструментов берёт только из `shared/tools.ts`, схемам от клиента не доверяет;
- превращает ошибки 401, 429, 529 и сетевые сбои в понятные коды и не раскрывает при этом детали и ключ;
- ставит заголовки CSP, `X-Frame-Options`, `nosniff` и `Referrer-Policy`.

## GitHub Pages

Сайт: **https://wwgame28.github.io/Rumbai/**

Workflow `.github/workflows/pages.yml` при каждом пуше в `main` прогоняет тесты, собирает статическую версию и публикует её. Один раз нужно включить Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Затем перезапустите workflow «Deploy to GitHub Pages» (Actions → Run workflow) или сделайте любой пуш в `main`.

- Работает всё, кроме облачного режима Claude: на Pages нет сервера, где мог бы храниться ключ. Интерфейс прямо об этом сообщает.
- Локальная модель, задачи, заметки, файлы и офлайн-режим работают.
- Локальная сборка той же версии: `npm run build:pages` (результат в `dist/`, путь задаёт `PAGES_BASE`, по умолчанию `/Rumbai/`).

Workflow `.github/workflows/ci.yml` на каждый pull request и пуш в `main` запускает проверку типов, линтер, модульные тесты, сборку и e2e-тесты Playwright.

## Деплой на Replit

1. Импортируйте репозиторий `wwgame28/Rumbai` в Replit (Create → Import from GitHub).
2. В Secrets добавьте `ANTHROPIC_API_KEY`, если нужен облачный режим.
3. Команда сборки: `npm ci && npm run build`.
4. Команда запуска: `npm start`. Сервер слушает `PORT`, который задаёт Replit.
5. Deploy → Autoscale или Reserved VM. Приложению нужен HTTPS: без него не работают service worker, WebGPU и установка PWA.

Подойдёт и любой другой хостинг с Node 22.6+: тот же сервер раздаёт статику и `/api`.

## Установка на iPhone

1. Откройте адрес развёрнутого приложения (HTTPS) в Safari.
2. Нажмите «Поделиться».
3. Выберите «На экран Домой».
4. Проверьте название (RUMBAI) и нажмите «Добавить».

PWA — это не нативное приложение: у него нет фоновых задач, доступа к календарю и контактам, push-уведомлений без отдельной настройки. Safari может удалить данные сайта при нехватке места; установка на экран «Домой» и кнопка «Защита от очистки» в настройках снижают этот риск, но не исключают его. Регулярно делайте экспорт.

## Локальная модель

Экран **Ещё → Локальный ИИ**:

1. Блок «Возможности браузера» показывает фактическое состояние: WebGPU, наличие шейдеров f16, адаптер, квоту хранилища.
2. Выберите модель и нажмите «Скачать и запустить». Перед загрузкой появится подтверждение с размером; без него ничего не скачивается.
3. После загрузки нажмите «Проверить инференс». Модель считается рабочей только после первого успешного ответа на этом устройстве.
4. На экране ассистента выберите «На устройстве».

Модели проверены по каталогу WebLLM 0.2.86 (`prebuiltAppConfig`) и по спискам файлов в репозиториях `mlc-ai` на Hugging Face:

| Модель | Загрузка | VRAM (f16 / f32) | Лицензия |
|---|---|---|---|
| Qwen2.5 0.5B Instruct (q4) | ≈ 290 МБ | 945 / 1060 МБ | Apache-2.0 |
| Qwen2.5 1.5B Instruct (q4) | ≈ 880 МБ | 1630 / 1889 МБ | Apache-2.0 |
| Qwen3 1.7B (q4, режим размышлений выключен) | ≈ 984 МБ | 2037 МБ / только f16 | Apache-2.0 |

Без шейдеров f16 используются варианты `q4f32`. Llama 3.2 и SmolLM2 в список не вошли: в их карточках русский язык не заявлен.

RUMBAI различает пять состояний, и каждое показывается отдельно:
1. интерфейс доступен офлайн (service worker);
2. документы доступны офлайн (IndexedDB);
3. модель скачана (кэш WebLLM);
4. среда выполнения запущена;
5. инференс подтверждён успешным ответом.

Если локальный ИИ недоступен, ассистент так и говорит и **никогда сам не переключается на облако**. Демо-режима с заготовленными ответами нет.

## Что работает офлайн

**Работает без сети** (после первой загрузки по HTTPS):
- интерфейс;
- задачи, заметки, поиск, база знаний, импорт файлов;
- автоматизации;
- экспорт и удаление данных;
- локальный ассистент, если модель уже скачана.

**Нужен интернет:**
- облачный ассистент (Claude);
- первая загрузка модели (Hugging Face и GitHub);
- проверка статуса сервера.

## Агент и инструменты

Инструменты описаны в `shared/tools.ts` и выполняются в браузере, над локальными данными: `search_notes`, `search_documents`, `search_conversations`, `list_tasks`, `create_task`, `update_task`, `delete_task`, `create_note`, `read_document`.

Правила безопасности:
- **Чтение** выполняется без вопросов.
- **Запись** требует подтверждения, пока в настройках не включено «Создавать и изменять без вопросов».
- **Удаление** подтверждается всегда.
- Аргументы проверяются схемой до выполнения.
- Каждое действие попадает в журнал: только тип действия, id и исход, без текста сообщений.
- Импортированные документы и результаты инструментов передаются модели как недоверенные данные, а не как инструкции.

Инструменты работают в облачном режиме, через встроенный tool use у Claude. Маленькие локальные модели ненадёжно вызывают инструменты, поэтому в локальном режиме это обычный чат: в нём нет инструментов, но есть документы в контексте.

Поиск по знаниям текстовый: по словам, без учёта регистра и «ё». Семантического поиска с эмбеддингами нет, и интерфейс об этом сообщает.

## Структура

```
.
├── .github/      CI и публикация на GitHub Pages
├── server/         Node-сервер: статика, /api/health, /api/chat (Claude), безопасность
├── shared/         общий код: протокол чата и схемы инструментов (zod)
├── pwa/            шаблон service worker; vite.config.ts собирает из него dist/sw.js
├── public/         манифест, иконки, offline.html
├── src/
│   ├── app/        оболочка, навигация, баннеры, тема, клавиатура
│   ├── ui/         Sheet, Dialog, Toast, Segmented, Switch, Orb, focus trap
│   ├── styles/     дизайн-токены (тёмная и светлая темы), компоненты, экраны
│   ├── motion/     пружины и варианты анимаций Motion
│   ├── data/       IndexedDB (версии и миграции), коллекции, схемы, экспорт
│   ├── ai/         WebLLM (воркер), определение возможностей, каталог моделей, клиент Claude
│   ├── agent/      выполнение инструментов и разрешения
│   ├── assistant/  контроллер разговоров: стриминг, остановка, повтор, правка, цикл инструментов
│   ├── automations/ шаблоны и запуск автоматизаций
│   ├── files/      импорт и извлечение текста
│   └── screens/    главная, ассистент, задачи, заметки, знания, файлы, автоматизации, модели, настройки
├── e2e/            тесты Playwright
└── scripts/        генерация PNG-иконок из SVG
```

## Технологии

React 19, TypeScript 6, Vite 8, Motion 14 (`motion/react`), lucide-react, idb, zod 4, @mlc-ai/web-llm 0.2.86, @anthropic-ai/sdk, marked + DOMPurify, шрифт Inter Variable (свой хостинг, кириллица), Playwright.

## Известные ограничения

- **Реальный инференс не проверен.** В облачной среде разработки нет GPU: headless Chromium не выдаёт адаптер WebGPU. Скачивание, запуск и ответ модели на iPhone нужно проверить вручную на устройстве, экран «Локальный ИИ» для этого и сделан.
- **Нет проверки на физическом iPhone и в Safari/WebKit.** Тесты шли в Chromium с вьюпортом 440×956. В CI можно добавить WebKit: `npx playwright install webkit` и `PW_WEBKIT=1 npm run test:e2e`.
- **Работа с Anthropic API проверена на подставном сервере.** Тесты используют поддельный upstream: стриминг, 401, 429, 529, отказ модели. С настоящим ключом проверки не было.
- **Нет извлечения текста из PDF и DOCX.** Такие файлы отклоняются с объяснением.
- **Нет синхронизации между устройствами.** Supabase не подключён.
- **Нет английского интерфейса.** Доступен только русский.
- **Автоматизации работают только при открытом приложении.** Интеграции с Telegram и календарём помечены как недоступные.
- **Два крупных чанка WebLLM (по ≈ 6 МБ).** Один грузится в основном потоке, другой в воркере. Они загружаются только при работе с локальной моделью и кэшируются при первом использовании.
